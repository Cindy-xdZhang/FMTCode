# Task4-c 固定线簇数据集 v1：构建规则（规范文本）

本文是 Task4-c 固定数据集的唯一规则来源。用户于 2026-09-18 分三次给出并细化这些规则（上午：样本定义与 step1–4；下午：hairpin 实例覆盖；晚间：距离改为 1h、放松阈值改为 100 次）。实现版本、作业与冻结哈希记在 [Task4C_fixed_dataset_protocol_1.1.md](Task4C_fixed_dataset_protocol_1.1.md)；本文只写规则。规则与实现不一致时以本文为准，并必须先改实现再重建。

## 0. 为什么要固定数据集

过去的流程是“采样点 → 线束 → 清理 → 保存清理后的线束”。因为保存的是清理后的线束而不是采样点，一旦要求 16 个邻居或固定中心线，就有样本不满足条件，只能重建数据集。v1 之后不再如此：数据集一次建好、长期只读。改变邻居数（k ≤ 16）、邻居选法（FPS＝farthest point sampling 最远点采样、最近邻、按逐线标签筛选）、是否固定中心、逐线重采样点数、编码或网络，都只在读取阶段完成，**不重建数据**。

## 1. 样本定义

1. 一个样本本质上是三维空间中的一个**采样点**（中心）。从它出发积分得到的涡线是**中心线**。
2. 以中心为原点的 3×3×3 立方模板上的 26 个点是**邻居播种点**，各自积分得到邻居线。模板间距为 0.25h、0.5h 或 1h（h 为当地网格间距的几何平均）。
3. 中心线加邻居线构成**线束**。线束是采样点的派生物，不是样本本身；采样点与线束按键值对方式一起保存（见第 7 节）。

## 2. 构建步骤（每个样本）

**step1 筛选播种点——只对中心。** 中心必须满足 λ₂ 涡判据（λ₂ < 阈值；Channel −13.395，TBL −0.0272）且展向涡量脉动 oyf > 0。头区样本的中心还须落在同一连通头区内；GT 头部样本的中心还须在指定人工 GT 实例内并满足头部夹角条件（|cos(速度, 涡量)|² < 0.5）。**26 个邻居播种点不施加 λ₂ / oyf / 同头区筛选**，只要求落在计算域内（域外点不积分，也不计入线数）。

**step2 积分。** 每个播种点沿涡量向量场（RK45）双向积分。单方向目标长度：Channel 0.08 / 0.10 / 0.12，TBL 4 / 5 / 6。步长与最大步数沿用 GTHeadCoverage 1.1 的冻结值（Channel 0.001/80、0.002/50、0.004/30；TBL 0.025/160、0.05/100、0.04/150）。三种模板间距 × 三种长度 = 九种尺度，配额在九种尺度间均分。

**step3 逐条曲线清理。** 删除非有限值或点数 ≤ 2 的曲线、任一半线实际弧长不在 [0.95L, 1.002L] 内的曲线、去重后点数不足或任一坐标轴跨度为 0 的曲线；其余按弧长均匀重采样 32 点。**保留条件：中心线通过清理，且至少 16 条邻居线通过清理（≥ 17 条有效线）。** 不满足则丢弃该采样点，在同一来源重新播种。因此任何 k ≤ 16 的邻居选法以后都不需要重建。

**step4 放松。** 同一来源（一个头区、一个 GT 实例或一个配对目标）连续 **100 次**试探都无法产生满足保留条件的样本时，放松该中心的 step1 筛选（λ₂ ∧ oyf）：头区来源在该头区包围盒外扩一个网格间距内均匀采样，GT 来源从该实例未过滤的 GT 单元采样。放松后的样本可能是负样本。**放松样本的标签按中心点的人工 GT 归属决定**（中心落在某 hairpin 实例内为正类并记该实例，否则为负类），并标记 `relaxed=True`、`neighbor_filter=2`。再 1000 次仍失败则构建报错，不再进一步放松。

用户的备注保留于此：step1 过滤在原始论文中的作用，很可能只是把负样本过滤掉；v1 保留 step1 只为与旧数据可比，并用放松机制补足配额。

## 3. 标签

- 头区样本：沿用整头区的 GT 覆盖规则（单一实例覆盖 ≥ 50% 为正，零覆盖为负，其余排除）。
- GT 头部样本、配对样本：中心在某 hairpin 实例内即为正，记该实例。
- 放松样本：中心点 GT 归属。
- GT 实例编号 0 是有效实例。

## 4. Hairpin 实例覆盖与实例划分

**覆盖的定义。** 某划分“覆盖”一个 hairpin 实例，指该划分在此实例的头部区域内有 **≥ 2 个采样点**。头部区域 = 采样点在该 GT 实例体积内，且满足头部夹角条件（|cos(速度, 涡量)|² < 0.5）。构建时以每实例 10 个头部采样点为目标（能达到就采到 10 个），2 个是硬性下限。

**划分。** 每流场用固定种子把 hairpin 实例分为 **训练覆盖组 80%** 与 **未见组 20%**；GT 包围盒重叠的实例绑在同一组。Channel 74 个实例约 59 / 15，TBL 58 个约 46 / 12。

- 训练集必须覆盖训练覆盖组的**每个**实例。
- 未见组实例在训练集与验证集中完全不出现：其 GT 包围盒外扩一个中值网格间距为排除区，训练/验证中心不得落入。
- 测试集必须覆盖**全部**实例。训练覆盖组的实例用“轻微偏移”的测试点（第 5 节）；未见组的实例直接在其头部区域新采样。
- 验证集从训练覆盖组实例所在的头区空间块里划出（第 6 节），并满足第 5 节的距离规则。
- 负类头区（无 GT 重叠的涡头区）跟随离它最近的 hairpin 实例的分组：靠近未见实例的负类头区只进入测试集；其余按 3/1/1 空间块分给训练/验证/测试。

## 5. 距离规则与生成顺序

h 取该行中心处的当地网格间距几何平均（`local_grid_scale`）。

| 规则 | 数值 | 说明 |
|---|---|---|
| 评价点（验证、测试）距任意训练中心 | **≥ 1h** | 用评价行的 h |
| 训练覆盖组实例的正类测试点距同实例训练中心 | **≤ 6h** | 用测试行的 h；这就是“轻微偏移” |
| 测试中心距验证中心 | ≥ 0.5h | 用测试行的 h；实现方的选择，用户未另行规定 |
| 训练/验证中心与未见实例 GT 包围盒 | 不进入外扩 1 个中值网格间距的排除区 | |
| 同一划分内 (中心, 尺度) | 唯一 | 同一中心可配三种积分长度 |

**生成顺序 test → validation → train。** 先生成测试（每实例先采 GT 头部行，再补头区行），再生成验证，最后生成训练。训练里，每个训练覆盖组实例的正类测试点先在同实例内 1h–6h 环带上配对生成一个训练中心（该中心同时满足 GT 归属与头部夹角，因此计入覆盖）；配不到的测试正类删除并重新核对覆盖。随后每个覆盖实例补 GT 头部训练行到目标数，再用头区行填满配额。

## 6. 配额（每流场；两流场合计翻倍）

| 划分 | 行数 | GT 头部行 | 头区行 |
|---|---:|---|---|
| train | 90,000 | 每个覆盖实例目标 10、下限 2（配对行计入） | 余量按九种尺度均分，轮询训练池头区 |
| validation | 1,500 | 无 | 同上，验证池 |
| test | 6,000 | 每个实例目标 10、下限 2 | 同上，测试池（含未见组头区全部单元） |

## 7. 存储格式（每流场每划分一组文件）

采样点与线束显式成对保存，每条线带自己的标签：

- `geometry.npy` float32 [N, 27, 32, 3]：整束质心/最大半径归一化后的线，**第 0 槽恒为中心线**，`counts` 之外补零。
- `seeds.npy` float32 [N, 27, 3]：同一归一化坐标系下的播种点。
- `metadata.npz`：`labels`、`counts`、`instance`、`head_component`、`scale_id`、`center`（物理中心）、`centroid`、`radius`、`neighbor_distance`、`local_grid_scale`、`ds`/`maxiteration`/`requested_half_length`、`half_arc_lengths`、`half_step_counts`、`nearest_train_center_distance`、`nearest_same_head_train_center_distance`、`source_cell`、`center_number`、`bounds`、`seed_rms_distance`、`measured_mean_arc_length`（22 键，旧驱动可直接读）。
- `index.npz`：`sample_kind`（0 头区 / 1 GT 头部）、`relaxed`、`neighbor_filter`（1 仅域内 / 2 放松）、`original_center_id`（恒 0）、`nearest_instance`、`heldout_instance`、`center_gt_owner`、`center_in_gt_head`、`offset_test`（训练覆盖组实例的正类测试行）、`paired_test_center`（训练行配对的测试行号，无则 −1）。
- `line_seed_attributes.npz`：`seed_points` float64 [N, 27, 3] 每条线的物理播种点（模板点精确坐标）、`stencil_slot`（0 中心，−1 填充）、`lambda2`、`oyf`（播种点三线性插值）、`inside`、**`head_candidate` = inside ∧ λ₂ < 阈值 ∧ oyf > 0（即 step1 条件的逐线版本）**、**`oyf_positive`**、`lambda2_threshold`。

读取时：中心线 = `geometry[i, 0]`；邻居 = 槽 1..counts−1；要“只用 step1 合格的邻居”就用 `head_candidate` 筛，要 FPS-k 就在邻居上做最远点采样，都不重建数据。

## 8. 核验（audit-data）

从原始场重新计算并逐行检查：中心在第 0 槽；≥ 17 线；半线长度与步数；几何归一化；(中心, 尺度) 唯一；逐线播种点与模板点逐位相等；λ₂ / oyf / 标签重插值一致；非放松中心满足 step1；GT 行标签与实例；放松行标签 = GT 归属；训练/验证不含未见实例且不进入排除区；每实例覆盖 ≥ 下限；1h / 6h / 0.5h 距离；配对行的距离在 1h–6h 内。通过后 `data_audit.json` 内 30 份文件的 SHA-256 即冻结哈希。

## 9. 冻结政策

- **无需重建**：邻居数 k ≤ 16 及选法、固定中心或标明的轮换对照、逐线重采样点数（如 48 点）、编码归一化与特征配方、网络与训练规则。
- **必须建新数据版本**（换版本号，保留 v1 文件）：改变积分长度/步长、清理阈值、λ₂ 阈值或 step1 筛选、标签规则、配额、实例划分或覆盖/距离规则、流场快照。
- 引用：论文与表格中称“Task4-c 固定线簇数据集 v1”，注明实现版本与冻结哈希。BottomDensity 1.2 / GTHeadCoverage 1.1 的旧数据只作历史结果来源，不再用于新实验。

## 10. 规则参数汇总

| 参数 | 值 |
|---|---|
| λ₂ 阈值 | Channel −13.395；TBL −0.0272 |
| 模板 | 3×3×3，间距 0.25h / 0.5h / 1h |
| 单向积分长度 | Channel 0.08 / 0.10 / 0.12；TBL 4 / 5 / 6 |
| 清理 | 半线弧长 ∈ [0.95L, 1.002L]，32 点重采样 |
| 保留 | 中心线 + ≥ 16 邻居线 |
| 放松 | 同一来源连续 100 次失败；再 1000 次报错 |
| 覆盖 | 每实例头部区域 ≥ 2 点（目标 10）；训练覆盖 80% 实例，测试覆盖全部 |
| 距离 | 评价点距训练 ≥ 1h；偏移测试点距同实例训练 ≤ 6h；测试距验证 ≥ 0.5h；未见实例排除区外扩 1 格 |
| 配额 | 每流场 90,000 / 1,500 / 6,000 |
| 种子 | 实例划分 98101（+流场序号）；采样 98201 |
