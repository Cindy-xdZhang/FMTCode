# Verify_Task6_PNNTrans_1.3 — 三倍训练集与学习率调度

2026-09-11 用户要求把训练集扩大约三倍，并增加学习率和学习率调度器实验。旧1.1/1.2算法及结果冻结；本版沿用1.2选出的c11网络，只搜索优化参数。目标是改善Task6几何重建泛化，不预设胜出。方法结论只写入`docs/experiment_log.md`。

## 数据及固定结构

每流场训练primitive由1024增加至3072；取冻结4.1缓存中同一随机排列的前3072项，完整包含前1024项，并保留同一train/validation/test时间窗。九个流场分别训练，validation仍各12000个，未使用test选择配置。准备阶段核对缓存哈希及旧1024样本索引前缀。Cylinder仍在原始[0,15]中的[7.5,12]播种；不能重新截半现有窗口。

空间前端仍为冻结1.1 Point-NN算子；逐帧特征经训练集尺度处理和可训练投影，进入6层、256宽、8头Transformer，压缩到192维，再由768宽、4残差块全连接解码器恢复7×32×3几何。Dropout=0.2、AdamW权重衰减0.01、特征噪声0.01、50%训练几何混合保持c11设置。没有原始几何跳接、解析逆变换或PCA。确定性自编码器，不称为VAE。

训练统计量仅由3072项拟合，验证/测试无噪声和混合增强。几何混合是训练集内凸组合，并重新计算Point-NN；不能把合成几何计作新增真实积分样本。

## 九组学习率/调度器

| ID | 基础/峰值学习率 | 调度器 |
|---|---:|---|
| l00 | 0.0001 | 原1.2预热×余弦衰减 |
| l01 | 0.0003 | 原1.2预热×余弦衰减；固定参考组 |
| l02 | 0.001 | 原1.2预热×余弦衰减 |
| l03 | 0.0001 | OneCycleLR，单周期先升后降 |
| l04 | 0.0003 | OneCycleLR，单周期先升后降 |
| l05 | 0.001 | OneCycleLR，单周期先升后降 |
| l06 | 0.0001 | 预热后ReduceLROnPlateau，验证停滞时降低 |
| l07 | 0.0003 | 预热后ReduceLROnPlateau，验证停滞时降低 |
| l08 | 0.001 | 预热后ReduceLROnPlateau，验证停滞时降低 |

原余弦公式保持1.2：`base * min(1,(step+1)/warmup) * (0.1+0.45*(1+cos(pi*step/(updates-1))))`，末端为base的10%。单周期用PyTorch OneCycleLR：前10%更新升到峰值，余下余弦降低；初值=峰值/25，末值=峰值/10000，`cycle_momentum=False`，只改变学习率，不同时调节Adam动量。

ReduceLROnPlateau前期线性预热到base；预热完成后只读取完整validation的RMSE/r，每连续3次未达到相对0.1%改善则乘0.5（PyTorch `patience=2`），最低base/100。第0步误差不参与调度和模型选择。记录每次验证的实际已用学习率、调度后学习率、最终调度器状态和PyTorch版本。

批次调度在`optimizer.step()`之后推进，平台调度在计算validation之后推进。API参考：[PyTorch OneCycleLR](https://docs.pytorch.org/docs/2.8/generated/torch.optim.lr_scheduler.OneCycleLR.html)、[ReduceLROnPlateau](https://docs.pytorch.org/docs/stable/generated/torch.optim.lr_scheduler.ReduceLROnPlateau.html)。Ibex部署前读取的实际版本为2.6.0+cu118，行为以该版本测试和运行记录为准；初步代码核验还使用本地CPU运行时。

## 训练预算、对照及选择

- 保持batch128。筛选由4000增至12000更新、预热1200，每2000更新评价；完整比较由24000增至72000更新、预热3000，每3000更新评价。每个真实训练样本的平均批次抽取次数与上一版相同（完整训练3000次）；其中一半位置仍按原规则构造混合样本。训练数据和更新预算同时扩大，不能把跨版本结果解释为仅数据量的单因素消融。
- 冻结Raw基线**必须在相同3072项上重跑**：保留1.1 c1原128宽/3层结构、学习率0.0003、Dropout0.1、权重衰减0.001、12000更新和原代码。新旧数据量的Raw结果并列，不能沿用1024项的0.624913作为本版同数据对照。其更新预算与新方法不同，如实报告。
- 相同结构Raw使用与PNN相同的网络、候选学习率/调度器、数据及72000更新；只有输入表示不同。此对照用于判断Point-NN表示是否带来额外收益。
- 先九流场重跑冻结Raw（9模型），再在固定Cylinder Re160/F22/Smoke筛选9候选（27个PNN模型）。按相对于本版Raw的三流场平均验证误差比排序，保留前三名与l01；若l01已在前三，补第四名。共4候选，不把参考组排除。
- 四候选在全部九流场从随机权重重训两臂（72模型）。以九流场PNN等权验证均值选一套全局配置，不逐流场选择；Raw不独立择弱配置。总计108个开发模型，另有合成数据代码测试。
- 只有选定两臂及冻结Raw的每流场validation均<3，且PNN九流场均值低于两种Raw，才启动最终阶段。否则保留负面结果并停止，不读取测试集。

通过后仅在本轮3072样本规模、九流场、冻结种子94111/94112/94113下重训三臂，共81模型。每模型仍按validation选择正训练步，门槛失败不读取该模型的test；通过者各评价test/unseen_scale一次。该测试集是已使用的benchmark，不称新confirmation。先每流场平均三个种子，再对流场等权平均；不完整结果不得发布完整均值。

误差维持七条线31个非初始时间点的三维位置RMSE/r，不能换成逐坐标RMSE。重用既有独立预测复算代码。最佳权重仅存RAM，不保存/下载checkpoint。所有提交及运行事件记录`docs/ibex_run_registry.md`。
