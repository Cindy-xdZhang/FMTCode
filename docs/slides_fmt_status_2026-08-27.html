Motivation · why a fixed geometric encoder

Pathlines are not unordered point clouds

  • Point-cloud KNN discards both structures a pathline has — temporal order along a line, spatial correspondence across lines.
  • So we fix the unit — a pathline cross primitive — and test a Fourier encoder with no trainable parameters.
  • Training-free describes the encoder only — KMeans, VAE and classifier are still fitted.

Four questions, four tasks

  • A clusterable vortex representation on its own? Task 1
  • A better input to the same VAE? Task 2
  • A better supervised IVD classifier? Task 3
  • Does it survive varying scale? Task 5

Not whether FMT always wins — how far the gain extends, and where it breaks.

Method · the primitive

One seed, seven pathlines, a fixed tensor

Construction

Centre plus six axis neighbours, RK4, fixed semantic order:

center, x+, x−, y+, y−, z+, z−

[ N, 7, 32, 3 ]  →  672 flattened Every line resamples to 32 points, so the input shape is constant. Time is implicit in the sample order.

2D uses a 5-line cross; dropping to 5 in 3D would delete a spatial axis.

Method · FMT encoder, block 1

Rotation-invariant Fourier descriptors per line

F[k] = Σt Δc(t) e−2πikt/L,   k = 0 … 5 rFFT of the differenced sequence. Differencing removes translation; neighbours are taken relative to the centre first.
R ∈ SO(3):   Δc ↦ R Δc  ⟹  F[k] ↦ R F[k] any Gram quantity of (Re F, Im F) is therefore invariant.
‖Re F[k]‖,   ‖Im F[k]‖,   cos∠(Re F[k], Im F[k]) 3 scalars per frequency → 18 per line.
χ[k] = ⟨Re F[k] × Im F[k], Re F[k+1]⟩ ⁄ (‖·‖‖·‖‖·‖) Normalised triple product — invariant under rotation, sign-flipping under reflection. 5 slots per line.

Why chirality is explicit

Handedness separates clockwise from counter-clockwise swirl. An earlier version kept one side of the spectrum, collapsing clockwise features to ~8% of the counter-clockwise norm. Fixed and regression-tested.

Neighbour aggregation

  • Sort-pooled over the six neighbours — invariant to relabelling.
  • Neighbours weighted 0.5 against the centre.
  • 23 per line × 7 lines → 161D.

Method · FMT encoder, blocks 2–3

Deformation and kinematics of the cross itself

Time-local Gram block

G(t) = D(t) D(t)⊤,   D Q⊤Q D⊤ = G D(t) ∈ ℝ6×3 holds the neighbour offsets. Unchanged by any time-dependent rigid observer — translation cancels in the offsets, rotation in the product. 21 series, trace-normalised, Fourier encoded.

Kinematic block

L = Ḋ D+,   ω = 2 axial(Lskew) Opposite pairs estimate the flow-map differential. A uniform observer spin adds the same skew everywhere, so the per-slice mean subtraction leaves an objective deviation.
‖ω − ⟨ω⟩‖,   ‖S‖F,   |∇·u|,   Q-like Q-like = ¼‖ω−⟨ω⟩‖² − ½‖S‖²F: signed rotation-versus-strain balance.

Method · reference label

One vortex label for every task

IVD(x, t) = ‖ ω(x, t) − ⟨ω(·, t)⟩Ω ‖ Vorticity magnitude after removing the volume's mean vorticity at that instant.
vortex(s) = 1  ⟺  IVD(s) ≥ P95(IVD over the volume) Per slice, over all voxels. No averaging window, no tuned radius.

Task 3 copies these labels bit-for-bit from the Task 1 / 2 caches, so two IVD implementations cannot drift apart.

Superseded label, kept on the record

v3.1 used a local criterion IVD > 0.9 × mean11³(IVD) with a hand-set 11³ box.

The two definitions flip the headline Task 3 conclusion (slide 17), so both are reported.

IVD is a proxy, not ground truth. Every claim below is about agreement with it on held-out slices.

Programme · evaluation discipline

The rules that make the numbers mean something

Splitting

  • Temporal splits only — spatial seeds are never split.
  • Leakage checked on the integration window (~14 frames), not the seed time.
  • Normalisation, PCA and KMeans centres fit on train.

Selection

  • Confirmation labels never touch features, VAE, checkpoint, threshold or α.
  • Each arm picks its checkpoint by its own development AP.
  • No “beat Raw by .02” rule; α fixed at 1.0.

Reporting

  • 5 training seeds; KMeans reports fixed random_state, n_init.
  • A wider Raw or matched Raw residual is mandatory.
  • Both macros reported; negative runs never deleted.

Honest boundary. The eight slices took no part in this round's training or selection, but earlier rounds saw them — held-out, not sealed.

Task 5 · mainExp_Task5_3D_1.1 · in flight

Does any of this survive when the primitive's scale changes?

Fixed-scale results assume one spacing and one horizon. Task 5 varies both per primitive — input shape, label, architecture and selection rules exactly as in v3.2.

What varies

  • Neighbour offset — in minimum grid spacings.
  • RK4 step size — a fraction of the source-frame interval.
  • Integration steps — horizon = step size × steps.
variable (offset, dt, n) → RK4 → resample → [ N, 7, 32, 3 ] Every tuple resamples to 32 points, so one network consumes all scales — the comparison is about geometry, not tensor shape.

Task 4 · not started

What must be frozen before vortex-type classification begins

Does FMT improve multi-class vortex-type classification — streamwise, spanwise, hairpin? No result exists.

Preconditions

  • Label provenance per dataset — IVD labels cannot be reused.
  • Background handling, frozen first — three classes inside a segmented region, or non-vortex as a fourth. Never mixed in one table.
  • Cross-dataset name mapping — type vocabularies differ by source.
  • Balanced metrics — class counts, macro-F1, per-class F1, confusion matrix.
  • Localisation error reported separately from type error.

The error to avoid

Task 3's binary results are never streamwise / spanwise / hairpin accuracy. They measure agreement with a scalar threshold, which carries no type information.

The most likely misreading of this result set — hence the boundary sits in the protocol, not in convention.
