## 需要保留在后续方法讨论中的实现问题

1. **候选区域并非完整的连续三线性条件交集。** `candidate_cells` 只允许至少有一个顶点同时满足两条件的单元。反例：单元 x 两端 `(lambda2,oyf)=(-1,-0.2)`、`(0.2,1)`，阈值 0；没有合格顶点，但中心插值 `(-0.4,0.4)` 合格，整个单元仍被初始池排除。可运行的反例见审查脚本。实际流场遗漏体积尚未量化，不能声称造成当前性能下降；用户已要求本次不重建。
2. **“距离最近实例”实际按 GT 单元中心近似。** `load_scene` 使用 `vtkCellCenters`，`assign_instances` 查询这些中心；不等于到完整标注单元体积/表面的精确最短距离。候选区域所属分量又采用最近候选格点的分量。两项是实现定义，不能误写成精确连续区域归属。
3. **旧 FPS 没有物理半径上限。** 最近 64 个样本作为候选池，从中心启动最远点采样，第一个取第 64 近的点。正样本全负邻居比例（全流场所有正中心）：Channel FPS6/FPS16 = 0.4675%/0.0762%；TBL = 0.5421%/0.0556%。比例支持“该情况存在”，不能证明是整体低 F1 的主因。
4. **几何查询跨折。** FMT 2.1 对同流场全部样本建树，包含测试折几何但不读邻居标签；因此不能称严格隔离的测试几何。旧 FPS6/FPS16 跨测试边界的邻居边约 Channel 0.76%/0.65%、TBL 1.11%/0.93%。本次配对实验保留此条件。
5. **验证与测试不是同一种泛化条件。** 验证随机抽训练折样本 10%，测试是新实例。独立复算 seed96611：p35/h0 FPS6 验证/测试 F1=0.794333/0.241171；FPS16=0.831109/0.246454。这证明验证—测试差距，尚不能单凭此判断距离、实例差异或过拟合各自的贡献。
