## 论文究竟学习什么

多层感知机（Multi-Layer Perceptron，MLP）是由全连接层和非线性激活组成的网络。该论文使用MLP近似一个已经给定的非定常流场的流映射：

\[
\widehat x(t)=f_\theta(s,c(t)).
\]

其中，`s`是粒子的播种位置；`c(t)`是要查询的保存时刻，即file cycle；`theta`是针对这个流场及指定时间范围训练的网络参数；输出是粒子在该时刻的三维位置。对于重新播种的时间块，`s`应解释为该块起始时刻的位置，而不是永远固定为全局最早时刻的位置。

轨迹在这里提供训练真值。推理输入只有位置和时间，**没有作为输入的pathline primitive，也没有FMT token**。因此作者的网络参数存储了特定流场的信息；我们的共享查询网络也通过权重学习训练数据的规律，但推理时还需要从每个primitive的token读取对应局部运动的信息。论文最接近固定流场的神经函数拟合与新播种点查询，并不直接证明某种轨迹token的质量。

主文第54–55页、图4：初始位置和时间各自通过一条全连接编码分支，拼接两条分支的结果，再通过全连接解码器输出位置。对一条完整路径线，在多个查询时间调用同一个网络即可；不是每次根据前一个预测点推进一个数值积分步。这里的内部latent vector是查询位置与时间的隐藏表示，也不是我们的primitive token。

## 数据怎样组织：先生成完整轨迹，再展开为位置—时间查询

主文第54页第3.1节和公式(1)将一个样本表示为`{start, file_cycle, end}`。用清楚的数组语义重写如下，下面是对论文的等价解释，不是声称其原始NPY必定使用这一轴顺序：

```text
positions[block_id, seed_id, saved_time_id, xyz]
start = positions[block_id, seed_id, 0, :]
input = (start, query_time)
target = positions[block_id, seed_id, saved_time_id, :]
```

若一个时间块有M个播种点，每条轨迹保存P个非初始位置，则可展开成M×P个位置查询训练样本。3D情况下，数值输入可写成`(M*P, 4)`，目标为`(M*P, 3)`；实际网络将4列拆成3维位置与1维时间两条分支。一个起点会在P个样本中重复，但每条样本监督不同的查询时刻。增加保存时刻产生的训练行并不等于增加独立播种点或独立流动几何。

论文正文有一句`m × n × n array`，与周围对种子、时刻和坐标的定义不吻合，不能照抄成确定的数据维度。公式(1)的样本定义是明确的；公开`LoadPointsData2`从每行读取前三维start、接下来三维end和末列time，`LoadPointsDataTest2`则从轨迹数组展开样本。两者支持上述样本语义。

### cycle、file cycle与interval

- `cycle`：一个模拟时间步，物理步长记为δ。
- `file cycle`：保存了粒子位置的那个模拟时刻。
- `interval I`：相邻两个保存时刻间隔的模拟步数，因此保存间隔为Iδ。
- `p`：hybrid时间块包含的保存间隔数，块长为pIδ。

file cycle不是另一条轨迹，也不是一个单独的速度场feature。它是查询时间的编码。论文半圆柱实验采用δ=0.1、I=1；Double Gyre、ABC、Gerris等部分实验采用δ=0.01、I=5。这些是作者的设置，不能直接替换本项目各数据来源的真实时间坐标。

### 三种轨迹组织方式

| 方式 | 构造训练数据 | 预测长轨迹时怎样查询 | 优点与不足 |
|---|---|---|---|
| Lagrangian_long | 开始时播种一次，记录从同一个起点出发的所有后续保存位置 | 用同一个初始位置分别查询各时刻 | 段内预测不递归累积误差；长时间后粒子分布可能变得不均，长映射也可能更难拟合 |
| Lagrangian_short | 每个保存间隔重新播种，每条短映射只存一个末位置 | 上一段预测终点作为下一段起点，逐段查询 | 各时间段重新覆盖空间；每一步都递归，容易积累误差 |
| Lagrangian_hybrid | 每p个保存间隔重新播种，但块内保存所有中间位置 | 块内直接由该块起点查询，块边界才传递预测终点 | 减少递归次数，并周期性补充空间覆盖；不会消除全部组合误差 |

证据：主文第54页图3、第56–57页第4.2.3节及图6。

**重新播种改变的是构造训练基准映射的采样集合，不是把正在预测的物理粒子重置回原始位置。** 推理长轨迹时，跨块必须继续使用该粒子上一块的预测终点。

例如以本项目Cylinder合规时间为例，块A为[7.5,8.5]、块B为[8.5,9.5]。A中采样一批起点，B中重新采样另一批起点，分别积分并保存块内轨迹。推理时从q出发，A网络直接查询8.0和8.5的位置；再将8.5的预测位置交给B，查询9.0和9.5。不能将B的训练播种点代替这个预测位置。

重新播种与训练多个网络是两个不同选择。图6分别比较long/hybrid以及一个/两个模型，不能误读成每个重播种块必然独占一个网络。若按时间分模型，需要计入全部模型参数及存储；一个模型覆盖多个重播种块时，时间输入必须能区分这些块，不能只给重复的局部时间和相同位置而丢失块对应的流动信息。

## 采样密度、划分和训练预算

主文第54页采用Sobol低差异采样，即比普通独立随机采样更均匀覆盖空间的一类确定性准随机点序列。论文引用前作作为优于随机/规则网格的依据；不能视为已经在我们所有流场上验证的结论。第58页同时说明，在与插值方法比较的非结构网格实验中使用了单元中心播种，不能说所有实验都使用Sobol。

重要的实际规模：

- 主文第56页Gerris复杂度实验：262,144个播种点、100个flow maps，按公式(1)约产生26,214,400个查询行。
- 主文第58页Hurricane实验：225万个播种点、30个flow maps，约6750万个查询行；100个epoch的训练约11小时。
- 主文第55–56页：额外生成相当于训练样本10%的验证数据，测试使用5000个随机播种点。正文没有给出完整可复现的空间去重距离及全部划分文件，不能补造为严格空间隔离协议。
- 非结构Half Cylinder只使用6752个种子，论文报告这一稀疏情况效果较差，并把更密播种和未来自适应采样作为改进方向；自适应采样在此处是未来工作，不是已经实现并验证的方法。

论文主要考查已学习流映射时间范围内的新播种点查询。补充材料第2/4页还用每5步保存的训练位置，测试每1步的位置，验证时间区间内的插值。它没有以此证明超出训练时间范围的外推或新流场泛化。

## 网络与优化能借鉴什么

| 项目 | 作者证据 | 对本项目的含义 |
|---|---|---|
| 宽度和深度 | 4/6/8层组合、1024/2048维拼接隐藏表示；较深配置在不少数据上较差，较宽配置常有帮助，但并非每个数据都如此 | 不能只按“参数更多”选择结构；应单独比较增加宽度和增加深度 |
| 正弦激活 | 第56页使用sin激活，并移除原ReLU网络中的LayerNorm，在所测数据上优于ReLU | 可测试正弦激活及配套初始化；该实验不证明它一定优于当前SiLU激活，也不证明FMT的优势 |
| 损失 | 第55页公式(2)明确L1平均绝对误差 | 可以作为损失对照；不能只换损失便归因于FMT |
| 学习率 | Adam；验证损失5个epoch未下降后学习率减半；激活对比中sin与ReLU分别使用5e-4、1e-4 | 应按自己的训练/验证曲线决定固定诊断，不从test选超参数 |
| 数据遍历 | 部分明确报告的实验训练100个epoch | 扩大数据后应报告实际查询曝光量和相当于多少遍数据，不只报告更新次数 |

公开`network.py`使用首层频率50、后续频率1的正弦和相应权重初始化。然而该文件的位置/时间隐藏分支按3:1分配，且解码末尾也附加Sine；正文图4展示等宽分支，文字说明输出层不使用sin。公开`train.py`还包含加载既有模型继续训练的具体示例。因此若后续复现，需区分“按2024正文复现”和“原样运行所找到的公开快照”，不能直接把此仓库当前示例当成每张论文表的配方。

作者查看器`ModelInference.js`会将坐标按模型bounding box映射至[-1,1]，输出再逆变换。当前`new_interface`快照始终保留原始seeds逐模型查询，ScalarFlow配置也明确标为long；不能拿这一个代码分支声称作者hybrid推理无需传递预测终点。

## 最直接的数据检查结果

1. 当前每个primitive/短段只监督8个查询种子。它们由坐标为±0.22r的立方体八角点共同旋转和缩放得到，同一primitive内距中心的半径相同。扩充训练区域8倍并没有把单个primitive的查询种子数量从8增加到64，也没有改成整个合法查询体积内的密集采样。代码为`FlowMapData_3D.py::query_offsets/randomized_queries`。
2. 当前支持轨线保留32个时间点，查询目标保留63个；`fit_direct`从全部62个非初始目标时刻中抽样训练。因此“输入采样间时刻”指标不是“训练监督未见时刻”指标。要复现论文附录的时间插值，需要单独排除一些监督时刻，再仅在这些时刻评估。
3. 当前扩大数据后保持30000次更新、每次64×16=1024个查询。在Re160中，Task6原数据共有906×8×62=449376个查询对，扩充后为7178×8×62=3560288个。30720000次随机查询曝光分别约等于68.36与8.63遍。Task7约从136.72遍变为17.26遍。这是有放回抽样下的等效曝光量，不是每条数据必定被恰好访问的epoch数；不能据此单独断言训练不足，但应作为下一轮预算设计依据。

上述是对冻结配置和样本结构的核对，不是新实验结果，也没有改变前一轮结论。

## 建议的下一轮顺序：先数据，再结构

**第一步：加入同时间窗口内的新播种点查询诊断。** 固定真实时间块，使用独立训练/验证/测试播种点；先确认能恢复没见过的粒子轨迹。旧的未见时间窗口评估保留为更严格的第二层。还应区分“同一支持primitive的新query”和“未参与训练的primitive上的新query”，只有后者进一步考查token对应的局部几何能否被共享网络解释。不能只做逐行随机划分而把同一轨迹的不同时间点分散到训练与测试后，称为新轨迹测试。

**第二步：增加每个primitive内部的查询密度。** 在合法query区域内使用独立Sobol点集，例如以64/128个query为候选，而不只增加primitive总数。覆盖中心、内部和近边界位置；Task7继续满足隐藏区域与全部可见输入的隔离。不同阶段的支持轨线与query真值分别积分；支持轨线不能混入隐藏目标。这里只是候选数量，尚未预注册或运行。

**第三步：Task8同时检查第二段查询覆盖。** 训练第二段不能只有中心附近少量query，却要求推理处理更大范围的到达点。应在训练数据上确定支持范围、query覆盖和段长，分别统计第二段直接查询误差、第一段到达误差以及完整组合误差。用真实到达位置查询第二段可以作为单独标明的诊断，但正式组合仍必须使用预测终点。若引入由训练集模型预测生成的扰动query，真值仍需从原流场积分；这是本项目的后续设想，不是作者已验证的策略。

**第四步：按数据规模安排训练曝光，再比较正弦网络。** 固定同一份数据、相同合法输入及测试划分，比较当前网络与正文启发的较宽、适度深度、正弦激活网络。先看完整训练曲线，分别报告参数量、更新次数、查询曝光量和GPU时间；不能同时更换采样、网络和损失后把所有改善归于某一个因素。

可额外设置“每流场/时间块一个坐标网络”的论文式拟合参照，以确认积分目标和坐标查询任务能被神经网络拟合。但它将流场存入权重，不是FMT条件查询的同信息基线，也不能单独支撑FMT作为flowmap tokenizer的论文主张。

本轮仅完成阅读、源码核对和建议整理；所有建议待讨论后建立新实验版本，原Task6/7/8协议、代码、数据与指标保持冻结。
