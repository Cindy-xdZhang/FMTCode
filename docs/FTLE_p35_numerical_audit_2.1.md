# FTLE P35 2.1：标准化审计修订

88次正式开发拟合与选择均完成，`pyramid_p35`按预注册规则通过门槛。原审计51907440失败于训练特征标准化参数的逐项复算：四个Raw均值元素超过rtol1e-8/atol1e-9，最大绝对差9.2824e-09。原日志、非零退出和全部预测保留。

训练代码先在float32数组上计算带符号log1p，再转换float64计算均值和标准差。Cylinder4×Raw训练缓存的独立诊断显示：本机重算与保存均值逐项相同；对float64对数参考，均值最大差9.0844e-09、标准差最大差4.7846e-09，标准化输入最大差9.1456e-07。float32对数本身最大绝对误差2.6514e-07。不同CPU节点的浮点函数实现是当前数值差异的合理解释；没有把具体指令分派视为已直接证明的原因。NumPy的[CPU运行时分派文档](https://numpy.org/doc/1.26/reference/simd/index.html)说明其会根据CPU能力选择实现。

修订只涉及独立审计，不重新训练、不改特征缓存、不改预测、不改门槛。原`Audit_FTLE_P35_Fusion_2_1.py`保持冻结。新增`FTLE_Statistics_Audit_2_1.py`，从原训练特征以float64独立计算带符号log1p及统计量；逐特征均值容许误差为`4 eps32 mean(abs(z))+1e-12`，标准差容许误差为`4 eps32 RMS(z)+1e-12`。这分别是点值舍入预算传播到均值和标准差的界，不能替换为针对观察到的某个最大误差设置统一容差。4 eps32是本次审计采用的保守点值预算，不声称是NumPy所有平台的函数误差保证。

标准差小于1e-8映射为1的规则继续检查，非恒定特征若在误差界内跨过该阈值则拒绝通过；常量列必须精确保持std=1。还检查使用保存统计量与独立参考得到的标准化输入最大差小于1e-4，并逐次记录实际差。原标量统计量、预测指标、已知节点、最佳轮次、代码/配置哈希及选择规则的检查不放宽。

新的开发审计`Audit_FTLE_P35_Numerics_2_1.py`复制原结果审计逻辑，仅替换统计量核对。最终审计采用同一独立函数；最终训练函数完全保留。失败与修订作业分别登记，原方法科学commit52ec9d8b仍是88次开发拟合的依据。
