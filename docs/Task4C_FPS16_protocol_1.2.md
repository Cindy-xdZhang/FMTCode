# Ablation_Task4C_FPS16_1.2：固定原中心、≥16 个域内邻居的线束重建与 FPS16 比较

版本 `Ablation_Task4C_FPS16_1.2`，接替两次在 pilot 阶段失败的 `Ablation_Task4C_FPS16_1.1`（bc41b003 因导入错误失败；8888eecb 因“同头区内不可能凑齐 17 个播种点”失败，见下）。目标不变：固定原三维采样点积分的中心线，以中心为起点用最远点采样（Farthest Point Sampling，FPS）选 16 条邻居组成 17 线 primitive，比较 p35/h0 与 c156，并配对各自的固定中心六邻居对照。四个模型、141 维特征、网络参数（76,738 / 992,386）、训练规则、seed 96721 与 1.1 完全相同，只改变数据重建规则。

## 1.1 失败的根因

冻结的 `FMT_Utils/Task4C_Multiscale_4_1.py:center_and_neighbors` 对 27 点模板的每一个点都要求 oyf>0 且其网格单元属于同一个连通候选头区。codex 在 r2 pilot 中的诊断（`outputs/Ablation_Task4C_FPS16_1.1/sampling_diagnosis/*.json`）显示失败层的头区只有 7–21 个单元，在 1.0h 间距下模板最多有 12–15 个点能留在头区内，因此“≥17 个播种点”在旧规则下结构性不可能；channel pilot 的 4,096 次试探中 46,963 次拒绝都是 `fewer_than_17_seed_points`，积分和清理只贡献约 500 次。重采样次数再多也无法成功。

## 用户 2026-09-18 决定

1. 样本的根本定义是一个三维采样点（中心）；邻居只是它周围的线。只有中心保留 step1 筛选（头区样本：oyf>0 且同头区；GT 头部样本：GT 归属、速度–涡量夹角、λ₂、oyf>0）。26 个模板邻居只要求落在计算域内，全部积分。
2. 一个样本必须“中心线通过清理且 ≥16 条邻居通过清理”（≥17 条有效线），否则丢弃并重新播种。
3. 连续 1000 次试探仍无合法样本时放松中心的 λ₂/oyf 筛选；放松后的样本标签由中心点的人工 GT 归属决定（在某 GT 实例内为正类并记该实例，否则负类），并在索引中标记 `relaxed`。
4. 只替换不满足条件 2 的行，保留其余旧几何。模板为最新完整数据 196,960 / 3,000 / 11,320 行（GTHeadCoverage 1.1，commit c3952a7b）。

## 数据规则

- 需替换的行：原中心线缺失或有效线 <17 的行；源核验时统计为 channel 37,072 / 616 / 2,429，TBL 34,971 / 632 / 2,089（训练/验证/测试），合计 72,043 / 1,248 / 4,518。其中 GT 头部规则行 958 训练、387 测试。
- 训练集先重建。随后对保留的验证/测试行检查“4h 内是否仍有同头区训练中心”；因训练中心被替换而失去该条件的保留行也一并替换（在 `replacement_index.npz` 与 `preparation.json` 中单列 `replaced_for_lost_same_head_train`）。
- 保持的层：流场、划分、尺度、头区/GT 头部标签规则、训练完整/下半区采样池。类别与 GT 实例只有放松行可能改变，索引保存 `source_label`/`source_instance`。
- 头区样本中心：与 4.14 完全相同的随机数流、单元选取和单元内抖动，因此同一 (head, center_number) 的中心与旧代码一致；不同之处只在邻居不再按 λ₂/oyf/同头区过滤。前 64 次试探优先原头区，之后允许同类别同实例的其他合格头区（与 1.1 相同）。
- GT 头部样本中心：沿用 `Task4C_GTHeadCoverage_1_1.candidate_points` 的候选点加 ±0.08 间距抖动，要求 GT 归属为该实例并满足头部夹角、λ₂、oyf>0；邻居只要求域内。
- 放松阶段（第 1000–1999 次试探）：头区样本在该层候选单元包围盒外扩一个网格间距的范围内均匀采样中心，不检查 λ₂/oyf；GT 头部样本从该实例未过滤的 GT 单元中心加抖动采样，要求仍在该实例内。两者的标签均取中心点 GT 归属。第 2000 次仍失败则整个构建报错，不再放松。
- 清理、积分参数与距离规则不变：RK45 沿涡量双向积分，Channel 单向 0.08/0.10/0.12、TBL 4/5/6，逐线 0.95L ≤ ℓ ≤ 1.002L，去重、坐标轴变化、32 点重采样；评价中心距任意训练中心 ≥1h、距同头区训练中心 ≤4h、测试距验证 ≥0.5h。r1 曾把全部旧中心作为间距检查的保留点；r2 起改为只针对最终数据集检查（见下节）。
- 替换行的中心固定在第 0 槽；保存全部通过清理的域内邻居（16..26 条）及 mask，以后 FPS-k（k≤16）不必重建数据。索引 `neighbor_filter`：0 = 保留的旧行（邻居经 λ₂∧oyf∧同头区过滤），1 = 新行（邻居仅域内），2 = 放松中心的新行。

已知不一致：保留的旧行邻居经过涡区过滤，新行没有；这是用户选择“只替换不满足条件的行”所接受的，逐行标记可供以后消融。

## r2 修订（同日，用户追加要求）

- **逐线属性文件** `line_seed_attributes.npz`（每个流场每个划分一份）：`seed_points [N,27,3]` 每条线的物理播种点坐标（重建行为模板点精确坐标，保留行由 float32 归一化 seeds 反算，误差 <1e-3 邻居间距）；`stencil_slot` 该线在 27 点模板中的位置（中心恒为 0）；`lambda2`、`oyf` 在播种点的三线性插值；`inside`；`head_candidate = inside ∧ λ₂<阈值 ∧ oyf>0`（step1 条件的逐点版本）；`oyf_positive`。填充槽为 NaN/False。播种点与线束因此成为显式的键值对，以后按标签筛选邻居或改变 FPS-k 都不需要重建。
- **距离规则改为针对最终数据集**。r1 pilot 中 channel 验证集有一个槽跑到第 1001 次试探才成功（进入放松阶段），拒绝原因几乎全是 `old_train_clearance`，即与即将被替换的旧训练中心保持 1h 间距。这些旧中心不在最终数据里，保留该检查只会把评价行逼进放松阶段并改变标签。r2 改为：训练行须距所有保留的验证/测试中心 ≥ 对方的 h；验证/测试行须距最终训练集（保留＋新）所有中心 ≥1h、距同头区最终训练中心 ≤4h；验证行距保留测试中心 ≥0.5h，测试行距最终验证集 ≥0.5h；旧中心只禁止坐标完全重合。`audit-data` 用最终文件复算这些距离。
- pilot 阶段的评价行以模板训练/验证集代替最终集合做上述检查（仅工程检查，不写入正式数据）。
- 数据核验新增：属性文件与 `seeds.npy` 反算一致、重建行坐标等于模板点、从原始场重新插值的 λ₂/oyf/标签与文件一致、非放松新行的中心 `head_candidate` 为真。

r1（同一科学代码，缺少逐线属性）在 Ibex 上完成源核验 52045843、GPU 预检 52045844（四臂 32 束 F1=1.0、参数 76,738/992,386）和两流场 pilot 52045845_0/1（新行 27 线占多数，最少 17，平均 1.6–6.4 次试探），重建 52045846 启动 1 分 42 秒后按上述原因取消，未写出数据；52045847–52045849 未启动。

## 比较

同一重建数据上配对四次完整训练：`p35_h0_fps16`、`c156_fps16`、`p35_h0_six_control`（最近 6）、`c156_six_control`（FPS6），全部固定原中心、无卷积、无轮换、seed 96721、batch 128、AdamW 0.001/0.0001、Dropout 0.15、最多 500 轮/早停 50、验证 F1 选轮、阈值 0.5。单种子报告，无跨种子标准差；模型只驻内存。测试结果按合并、分流场、保留行/替换行/放松行子集分别复算。

## 检查与执行链

本地 10 项测试（`tests/test_task4c_fps16_1_2.py`，含 r2 的模板点匹配与逐线属性检查）：新中心规则与冻结实现逐位一致且邻居全域内保留；中心 oyf 失败时两版本都拒绝；缺中心/不足 17 线的行判定；试探阶段表；放松中心按 GT 归属定标签；trace 门禁；装配只允许放松行改标签；配置沿用 1.1 四臂与完整模板。codex 的 1.1 五项测试保持通过。

Ibex 依赖链：`verify-source`（源哈希与需替换行统计）→ `gpu-check`（V100，四臂 32 束小拟合与跨批一致性）+ `pilot`（两流场，覆盖每个受影响 (类别, 实例, 标签规则) 与 (类别, 尺度) 层各一个槽，并实际写出装配文件）→ `build`（两流场完整重建）→ `audit-data`（保留行逐值不变、替换行中心在第 0 槽、≥17 线、长度、距离、放松/过滤标记）→ `train`（4 臂 V100，并发 4）→ `audit-results`（8 份预测复算）。任一阶段失败，后续不启动。

代码：`FMT_Utils/Task4C_FPS16_Data_1_2.py`、`experiments/Task4C_FPS16_1_2.py`；配置 `config/Ablation_Task4C_FPS16_1.2.json`；启动器 `ibex_bash/task4c_fps16_1p2.sh`。编码与网络复用 `FMT_Utils/Task4C_FPS16_1_1.py` 与 `FMT_Utils/Task4C_OriginalCenter_1_1.py`。

## 冻结政策（2026-09-18 用户裁定）

本版本生成的数据即 **Task4-c 固定线簇数据集 v1**，`audit-data`（52046107）通过后以 `data_audit.json` 的文件哈希冻结，长期只读。以后改变邻居数（k≤16）、邻居选法（FPS / 最近 / 按 `head_candidate`、`oyf_positive` 筛选）、是否固定中心、重采样点数、编码或网络都直接读取这些文件，不重建；改变积分长度、清理阈值、λ₂ 阈值或播种筛选、标签规则、模板行数或划分规则才建立新数据版本并换版本号。总协议 2b 节与 `Task4C_handoff.md` 3b 节为引用入口。
