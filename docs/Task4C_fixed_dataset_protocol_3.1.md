2026-09-19 用户授权尝试构建。版本 `mainExp_Task4C_FixedDataset_3.1`，输出 `outputs/mainExp_Task4C_FixedDataset_3.1/`。本版本继承冻结 v2 r3，只增加初始点与目标样本数量。v2 文件及正在运行的 ball query 2.5 实验保持原样；本轮只构建数据，没有训练作业。

## 数量与不变规则

| 项目 | v2 r3 | v3 |
|---|---:|---:|
| 两流场初始点总数 M | 4,000,000 | 40,000,000 |
| 两流场 Poisson 目标样本总数 N | 400,000 | 8,000,000 |
| 每流场 M / N | 2,000,000 / 200,000 | 20,000,000 / 4,000,000 |
| 每样本曲线数 / 每曲线点数 | 3 / 32 | 3 / 32 |

M 指在候选区域内通过筛选的初始点池，不是拒绝采样的总尝试次数。Channel/TBL 目标各占一半；沿用“三条长度全有效才保留、无效删除、不补采”，最终总数可能少于八百万，最终两流场比例也可能稍有偏差。800 万点对应清洗前最多 2,400 万条曲线。

候选区域、原始场及其哈希、Poisson 排列与半径二分容差、RK45 积分、清洗、GT 标签与实例归属均直接调用 `FMT_Utils/Task4C_FixedDataset_2_1.py`。完整旧规则见 `docs/Task4C_fixed_dataset_rules_v2.md`，已知实现边界见 `docs/Task4C_v2_review_2026-09-19.md`；本轮不夹带修正候选单元、最近实例或轴跨度清洗规则。

- 候选：Channel λ₂ < −13.395，TBL λ₂ < −0.0272，且 oyf > 0；保持旧候选单元支持与三线性插值判断。
- 单向目标长度：Channel 0.07 / 0.10 / 0.13，TBL 3.5 / 5 / 6.5；固定步长分别 0.001 / 0.025。一次最长双向积分截取三种长度。
- 半线一般要求 [0.95L, 1.002L]；仅离开计算域且该长度未完成的半线放宽到 [0.25L, 1.25L]。三线均清洗通过才保留，等弧长采样 32 点，不生成邻居。
- 标签来自播种点的 GT 单元查询；实例归属保持 GT 单元→GT 包围盒→候选分量→最近标注单元中心的旧优先级。
- **保留 v2 r3 的具体实例→折编号映射**，测试折仍为 0。旧分折算法按每实例样本数量平衡，密度改变会重新分配实例；为落实“别的不变”，v3 从旧 `preparation.json` 固定映射，只重新统计新样本数，训练/测试比例因此是近似 4:1。
- 随机数沿用唯一一套旧设置：初始池 98301+流场序号、Poisson 排列 [98302, 流场序号]、审计 98304+流场序号；没有重复随机种子实验。分折映射直接复用。

## 放大规模的工程处理

旧 dart throwing 在整个包围盒分配密集网格，超过 300,000,000 单元直接失败。新增 `FMT_Utils/Task4C_FixedDataset_3_1.py` 用开放寻址哈希保存已占用单元，内存随接受样本数增长；保留相同点顺序、27 单元检索、float64 严格距离 `< r²` 拒绝条件，不改变选点规则。测试逐项比较旧/新索引、半径搜索轨迹、重复点及距离恰等于半径的情况。

v3 通过独立函数作用域调用旧构建、清洗与审计，未修改冻结源码。保留旧初始池批量大小 2,000,000 和积分批量 4096；每流场申请 4 CPU / 96 GiB，最多并行两流场，不用 GPU。曲线坐标上限约 9.22 GB（十进制，不含元数据）；开始时要求至少 40 GiB 可用存储。最终空间与耗时以运行报告为准。

命令入口 `experiments/Task4C_FixedDataset_3_1.py`；启动器 `ibex_bash/task4c_fixed_dataset_3p1.sh`。科学身份保存 commit、配置和源码哈希；主机名只写运行日志，避免不同 CPU 节点造成科学身份误判。

## 提交与核验

链：输入/旧折来源/单元测试核验 → 两流场 pilot（各 200,000 初始点 / 40,000 目标，与正式同为 5:1 降采样）→ 两流场正式 build → 全量 audit-data。仅前序成功才放行，失败依赖自动取消，不自动增加种子或训练。

pilot 保存后另用旧密集网格算法重建全部初始池与 Poisson 搜索，要求半径、完整二分记录和保留点来源相同，复核全部标签、间距与具体折映射，并各重新积分 500 点。两份 `pilot_check.json` 均完成且科学身份一致才能进入正式构建。

审计保持 v2 全部检查：文件哈希、逐点候选/标签/归属、Poisson 最小距离、重建初始池与选点索引、同一半径可行及扩大后不可行、全部曲线弧长与几何、每流场 500 个样本重积分、同实例单折；另核对 v3 数量和具体折映射与 v2 完全一致。`data_audit.json` 完成后才称为已冻结数据集。
