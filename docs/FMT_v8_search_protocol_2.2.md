# FMT v8.2池化搜索：确定性执行修订2.2

用户2026-09-15授权的约50组池化与训练配置搜索继续，版本`Ablation_FMTv8_Search_2.2`。输入与目标沿用2.1：中心频域23＋方向频谱72＋邻居频域138，不增加角度或kin/IVD估计；Task3、Task5、Task4-c 4.14三任务等权平均F1相对原V8提高15%–20%为目标，分任务变化同时报告，不预设达成。

## 修订原因与证据

2.1在初期对照核验时停止，未完成50组，也未进入选择或测试。Raw坐标、标签、归一化统计逐值一致；差异在不使用池化的Raw骨干首轮就存在。旧训练未开启确定性CUDA运算。同卡诊断`Verify_FMTv8_Repeatability_1.1`、job51897403、代码commit5c547064，在相同V100、seed40、训练数据上各重复两次3epoch：默认模式两次权重最大差异0.0111464，确定性模式两次权重逐值相同（差异0）。2.1失败/取消及部分验证结果全部保留，不用其选择新方法。

此前要求逐值复现历史非确定性训练的检查不合适。2.2明确固定`cudnn.benchmark=False`、`cudnn.deterministic=True`、`torch.use_deterministic_algorithms(True)`及`CUBLAS_WORKSPACE_CONFIG=:4096:8`。原V8、全部候选和最终配对比较共用这些设置。旧v8.1指标保持；历史指标与新确定性原V8并列，最终增益只与本批同种子原V8比较，不把执行设置变化记成池化收益。

## 固定候选、训练与选择

50个执行配置及h0/h1/h2/h3的全部定义见`config/Ablation_FMTv8_Search_2.2.json`，与2.1完全相同；详表参见`FMT_v8_search_protocol_2.1.md`。其中p31/p40、p29/p45各数学等价，因此为48种不同表示；保留两对独立执行作为一致性检查。后续前三种池化选择会跳过数学等价项，确保细化的是三个不同表示。

1. 先真实训练子集工程预检，然后为Task3/5的20个任务/流场单元各训练一个Raw和Raw-wide共同骨干；Task4-c准备固定缓存。
2. 各单元先将原p00/h0重复训练两次，同一公共骨干、seed40或96611。21对验证概率、标签、阈值和选定epoch必须逐值相同，才启动完整搜索；首个结果计入50候选中的p00，第二个仅用于重复性检查。工程额外耗时单独记录。
3. 执行全部50配置：21个p00首结果复用，另1,029次拟合。各任务先分别平均流场，再对三任务等权平均验证F1。选前三种不同表示，各测试h1/h2/h3，共189次；含已试h0后总计59个候选、1,239次主验证拟合。
4. 按共同验证评分选唯一配置，参数更少及固定ID作为并列规则。锁定后，Task3/5用新种子44/45/46、Task4-c用96621/96622/96623，对选定配置和原p00/h0配对重训。读取已用测试benchmark一次，不据测试改参数；通常126次，若选中原V8则去重为63次。

三个任务的学习率、标签、模型骨干、融合、阈值、早停等除预注册h1/h2/h3因素外均保持。h0原训练、h1加强辅助dropout/weight decay、h2改变激活和学习率、h3对中心/方向/邻居分别作神经投影。h3属于可训练网络，不宣称固定FMT增加了可训练参数。Task3/5 h0/h1/h2总参数142,914，h3按实际值报告；Task4-c随输出宽度变化参数，逐次登记。
