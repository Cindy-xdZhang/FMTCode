## 范围和固定规则

每流场仍产生20,000,000个通过条件的初始点，Poisson降采样到4,000,000个目标点；两场合计M=40,000,000、N=8,000,000。每点三条长度，清洗不补采，所以最终总数仍可能少于800万。保持[3.1协议](Task4C_fixed_dataset_protocol_3.1.md)的流场、候选条件、积分、弧长/几何清洗、标签和归属；复用v2 r3具体实例→五折映射。只有采样分布和Poisson的类别配额发生改变。

正类严格定义为播种点位于GT标注单元（`sample_gt`返回实例号≥0，实例0有效），负类为其余候选点；包围盒、头区归属和最近实例不改变标签。后续h保持Channel0.003909492、TBL0.117239990，本轮无邻居线或训练。

## 采样概率与空间间距

1. 在原候选区域内按类别分别做物理体积均匀采样。正类提议限制到与任一GT包围盒相交的候选网格单元，并再次精确查GT单元；包围盒只减少拒绝次数，不把盒内全部点当正类。负类从全候选单元提议，再排除GT内点。两类都保留原三线性λ₂和oyf判据。
2. 初始点池按正类概率p分配固定数量，负类为1−p；类内仍均匀，全部点为新随机位置，无重复复制或训练损失加权。M是接受后初始点数，拒绝提议次数另记。
3. 对混合池使用原固定种子的随机排列；全局Poisson过程增加正负配额。某类填满后跳过该类，其余点仍须与**所有已接受点（包括另一类）**至少相距同一个半径。沿用原半径搜索与1e−4容差，寻找能同时填满两类配额的可行半径。不能只把初始池改为2:1却任由降采样改变输出比例。
4. 正类体积较小但数量提高，所得全局最小间距可能比3.1更小。这是用户要求的正类密度提高；不再把全候选域的采样密度称为均匀。类内随机提议均匀，最终仍全局Poisson分离。

新代码 `FMT_Utils/Task4C_FixedDataset_3_2.py`；原3.1/v2代码不修改。稀疏Poisson哈希保留float64严格距离判定，与独立全对距离参考逐项核对，包含异类紧邻点、半径边界和重复坐标。

## 清洗保留率修正与验收

每流场先做200,000→40,000的试构建，初始正类比例p=2/3；沿用相同唯一随机数设置，未增加实验种子。记录两类积分前数量和三条线全部通过后的数量，得到保留率s₊、s₋。正式构建采用

`p = 2*s₋ / (s₊ + 2*s₋)`。

因此预期清洗后 `p*s₊ / ((1−p)*s₋) = 2`。校准仅使用试构建的有效性，未使用模型结果；两场各自校准，锁入带来源哈希的 `calibration.json`。正式M、N仍不变，只调整两类配额，不通过复制正例或清洗后删负例凑比例。

“接近2:1”的本次验收范围设为每流场**1.9:1–2.1:1（相对2:1的±5%）**。达不到则构建/审计失败，不称完成，也不自动改变规则或补采。校准不能保证每个实例、每折完全相同比例；保持旧实例划分，并完整报告每折正负数量，防止为凑比例移动实例。

单套随机数继续为pool98301+流场序号、Poisson[98302,流场序号]、审计[98304,流场序号]。本轮改变分布，故点集与3.1不同；不能沿用3.1邻居表或训练缓存。新测试分布的F1也不能直接当作旧测试分布上的提升。
